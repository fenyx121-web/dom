# storybot: автомонтаж сторис из видео с Ray-Ban Meta

Присылаешь сырые ролики с очков боту в Telegram (или кидаешь в папку), через пару минут
получаешь готовые сторис 1080×1920: лучшие моменты, нарезка под бит, музыка, громкость под Instagram.

## Что делает бот

1. **Анализ каждой секунды** видео: резкость, движение в кадре, громкость, речь.
   Тёмные куски (палец на объективе, очки в кармане), смаз, «пустые» статичные
   секунды без звука отбрасываются.
2. **Отбор лучших моментов.** По умолчанию остаётся примерно 65% годного материала
   (`keep_ratio`). Фраза не обрывается на полуслове: если человек говорит,
   кусок продлевается до конца фразы.
3. **Музыка.** Трек берётся из интернета (Jamendo, только лицензии CC, разрешающие
   коммерческое использование) или из своей папки `music/`. Бот сам определяет
   темп (BPM) и сетку битов.
4. **Склейка под бит.** Длина каждого куска кратна 1, 2, 4 или 8 долям (примерно по 2 с),
   поэтому все склейки попадают в ритм. Музыка продолжается от сторис к сторис
   без сброса.
5. **Звук.** Если в кадре говорят, музыка тихая и приглушается под голосом
   (sidechain). Если не говорят, музыка громкая, а живой звук остаётся фоном.
   В конце громкость нормализуется до −14 LUFS (уровень Instagram).
6. **Разбивка на сторис** по 15–60 с (по умолчанию целевая длина 30 с).
7. **Картинка** приводится к 9:16 1080×1920: `crop` заполняет кадр обрезкой
   краёв, `blur` показывает весь кадр на размытом фоне. Добавляется лёгкий
   контраст и насыщенность.

Несколько роликов, пришедших одной пачкой, склеиваются в одну историю по времени съёмки.

## Telegram-бот (основной способ)

Вы и друзья шлёте боту видео в Telegram, а он присылает готовые сторис.
Бот работает на вашем компьютере или на сервере, публичный адрес ему не нужен.

### Что понадобится (один раз)

1. **Токен бота.** Написать [@BotFather](https://t.me/BotFather), выполнить `/newbot` и скопировать токен.
2. **api_id и api_hash.** Зайти на https://my.telegram.org, открыть «API development tools»
   и создать приложение (название любое). Это нужно для локального сервера Telegram:
   без него бот может скачать видео только до 20 МБ, а с ним до 2 ГБ.
3. **Docker Desktop**: https://www.docker.com/products/docker-desktop/
   (Windows или Mac; на Linux достаточно `docker` и `docker compose`).

### Запуск

```bash
cd storybot
cp .env.example .env       # вписать токен, api_id, api_hash
docker compose up -d --build
```

Одноразовый шаг перед первым запуском: отвязать бота от облачного сервера Telegram,
иначе локальный сервер может не получать сообщения. Открыть в браузере
`https://api.telegram.org/bot<ТОКЕН>/logOut`, должно вернуться `{"ok":true,...}`.

Дальше:

1. Написать боту `/myid` и узнать свой ID.
2. Вписать его в `.env` в поле `ADMIN_IDS=` и выполнить `docker compose up -d`.
3. Добавить друзей. Каждый пишет боту `/myid` и присылает вам число, а вы пишете
   боту `/adduser 123456789`. Посторонним бот отказывает.

Посмотреть логи: `docker compose logs -f storybot`. Остановить: `docker compose down`.
Обновить после изменений в коде: `git pull && docker compose up -d --build`.

### Как пользоваться

- **Видео.** Присылаете одно или несколько видео подряд. Бот ждёт 15 секунд, нет ли
  ещё (или начинает сразу по `/go`), монтирует и присылает сторис.
- **Очередь.** Если бот занят чужим монтажом, он пишет, какой вы в очереди.
- **Личные настройки** у каждого свои:
  - `/fit crop|blur`: обрезка на весь экран или целиком на размытом фоне;
  - `/length 15-60`: длина одной сторис в секундах;
  - `/mood energetic|chill|travel|party|calm`: настроение музыки;
  - `/music on|off`: музыка включена или выключена.
- **Хранение.** Исходники и готовые сторис удаляются с компьютера через 24 часа.
- **Свои треки.** Если положить их в `storybot/music/`, бот будет брать их, когда
  нет ключа Jamendo.

### Где запускать

- **Свой ПК.** Бесплатно, но бот работает, только пока компьютер включён.
  Во время монтажа процессор заметно нагружен.
- **VPS** (2 ядра, 2–4 ГБ памяти). Платно, но работает круглосуточно.
  Команды те же: поставить Docker и выполнить `docker compose up -d --build`.

## Вариант без Telegram: папка в облаке

```
Очки → приложение Meta AI (импорт в галерею телефона)
     → Google Drive / Dropbox (папка, например, «storybot-inbox»)
     → комп/сервер с ботом (синхронизированная папка = inbox)
     → бот кладёт сторис в out/ → тоже синхронизируется в облако → телефон
```

Проще всего поставить на компьютер клиент Google Drive или Dropbox и указать
в `config.json` синхронизированные папки:

```json
{ "inbox": "C:/Users/Me/Dropbox/storybot-inbox",
  "out":   "C:/Users/Me/Dropbox/storybot-out" }
```

На Linux-сервере то же самое делается через `rclone` (`rclone bisync` по крону
или `rclone mount`).

## Установка

Нужны Python 3.10+ и ffmpeg (`brew install ffmpeg`, `apt install ffmpeg`,
на Windows `winget install ffmpeg`).

```bash
cd storybot
pip install -r requirements.txt
cp config.example.json config.json   # и поправить пути
```

### Музыка из интернета (Jamendo)

1. Зарегистрироваться на https://devportal.jamendo.com и создать приложение,
   чтобы получить **Client ID**.
2. Вписать его в `config.json` в поле `"jamendo_client_id"` или передать через
   переменную окружения `JAMENDO_CLIENT_ID`.
3. Настроение задаётся в `"music_tags"`, например `"chill+lounge"`,
   `"energetic+upbeat"` или `"travel+summer"`.

Без ключа (или если сеть упала) бот берёт случайный трек из папки `music/`.
Если и там пусто, сторис выйдут с оригинальным звуком.

> **Про права.** Бесплатный API Jamendo предназначен для некоммерческих проектов,
> а у треков бывают разные лицензии. Бот берёт только CC без `NC`/`ND`
> и пишет `credits.txt` с автором: его надо указывать в сторис.
> Если блог монетизируется (реклама, интеграции), надёжнее купить лицензию
> Jamendo Licensing или складывать в `music/` треки из платной стоковой подписки.
> Трендовую музыку из библиотеки Instagram автоматически вставить нельзя:
> её добавляют вручную в самом Instagram, а в боте для этого есть `"music_source": "none"`.

## Запуск

```bash
python -m storybot watch                 # следить за папкой inbox
python -m storybot run a.mp4 b.mp4       # обработать конкретные файлы один раз
```

Результат: `out/<дата-время>/story_01.mp4, story_02.mp4, …`, а также
`credits.txt` (кого указать за музыку) и `plan.json` (какие куски взяты).

## Настройки (`config.json`)

| ключ | по умолчанию | что это |
|---|---|---|
| `music_source` | `auto` | `auto` / `jamendo` / `local` / `none` |
| `story_min` / `story_target` / `story_max` | 15 / 30 / 60 | длина одной сторис, с |
| `keep_ratio` | 0.65 | какую долю годного материала оставлять (меньше = жёстче отбор) |
| `shot_max` | 6 | максимальная длина куска без речи, с |
| `fit` | `crop` | `crop` (на весь экран) или `blur` (целиком на размытом фоне) |
| `merge_clips` | true | склеивать пачку новых роликов в одну историю |
| `batch_quiet_sec` | 45 | сколько ждать новых файлов, прежде чем начать монтаж |
| `music_volume` / `music_volume_speech` | 0.85 / 0.22 | громкость музыки без речи / под речью |
